## 이 문서의 목적

M211 렌더팜(Maya / Arnold / Blender)이 동작 검증을 마쳤습니다. 이제 **학생 신청을 받고 예약을 배정하는 운영**을 졸업준비위원회가 맡아주시면 됩니다.

운영 방식은 작년 PRFS 1.0(강세영 선배)의 구조를 그대로 이어받되, 신청 양식과 집계를 자동화했습니다.

## 2. 운영 절차 — 3단계

```
1단계   신청 접수      팀별 신청 → 신청서 탭에 입력
2단계   타임블럭 배정   분량에 따라 자동 산정 → 확정 공지
3단계   예약 운영      학생이 직접 예약표에 입력 → 주 단위 점검
```

### 1단계 · 신청 접수

학생(팀)에게 아래 4가지를 받습니다.

```
팀 프로젝트명
팀장 학번
팀장 이메일
프로젝트 분량 (분)
```

받은 내용을 **`01_신청서` 탭**에 한 줄씩 입력하면 됩니다. **라이선스 / 주 타임블럭 / 주 사용시간은 자동으로 계산**되므로 입력하지 않으셔도 됩니다.

> 분량은 **최종 상영 길이** 기준으로 받으세요. "렌더해야 할 전체 컷의 길이"라고 안내하시면 혼선이 적습니다.

### 2단계 · 타임블럭 배정

신청이 다 모이면 **합계 행 아래 판정 문구**를 확인하세요. 자동으로 다음 중 하나가 표시됩니다.

```
수용 가능  —  주간 공급 128블럭 중 104블럭 신청
초과      —  주간 공급 128블럭보다 12블럭 많습니다. 산정 기준 조정 필요
```

초과가 뜨면 `01_신청서` 탭 **F열 수식**의 구간을 조정하시면 전체가 다시 계산됩니다.

```
=IF(E5<=3, 1, IF(E5<=6, 2, 3))
```

확정되면 각 팀에 배정된 블럭 수를 공지합니다.

### 3단계 · 예약 운영

학생이 **`02_예약표`** 에서 **시간 + 그룹**을 골라 직접 학번을 넣습니다. 졸준위는 주 1회 **`03_사용현황`** 탭만 보시면 됩니다.

- **남은 블럭이 빨간색(음수)** → 상한 초과. 해당 팀에 연락
- 미등록 학번이 보이면 삭제
- 하단 `주차별 전체 예약 블럭` 으로 전체 사용률 확인

## 3. 타임블럭 · 그룹 · 라이선스

### 왜 나누는가

렌더팜은 한 대의 장비가 아니라 **실습실 PC 전체**입니다. 한 팀이 계속 점유하면 다른 팀이 아무것도 못 합니다. 그래서 시간을 블록으로 나눠 예약제로 운영합니다.

### 시간 구조

```
타임블럭 1개 = 4시간
```

| | 사용 가능 시간 | 하루 블럭 |
| --- | --- | --- |
| **평일 (월~금)** | `19:00 ~ 11:00` | 4개 |
| **주말 (토·일)** | 24시간 | 6개 |

평일 낮 `11:00~19:00` 은 수업이 있어 제외합니다.

### 그룹 — 네 팀이 동시에 쓸 수 있는 이유

실습실 PC는 **4개 그룹(A·B·C·D)** 으로 나뉘어 있습니다. 한 타임블럭에 **네 팀이 서로 방해 없이 동시에** 렌더할 수 있습니다.

```
평일   5일 × 4블럭 × 4그룹  =  80 블럭
주말   2일 × 6블럭 × 4그룹  =  48 블럭
────────────────────────────────────
주간 총 공급                  128 블럭
```

> **이 그룹 분할이 아직 적용 전입니다.** 현재 복구 중인 Worker PC 정리가 끝나는 대로 담당자가 Deadline에 그룹을 생성하고 PC를 배정합니다. 완료 시점을 졸준위에 알려드리겠습니다.
>
> 2026.10.17 기준 **18대 가동** (M211-08 전원 불량, M211-12 수리 중). 이 중 M211-00은 라이선스 서버이므로 Worker는 17대이며, 4그룹 × 4~5대로 배정합니다.

### 라이선스

"라이선스"는 **주당 예약 상한**을 뜻하는 단위입니다. 소프트웨어 라이선스와는 다른 개념이니 학생 안내 시 혼동이 없도록 해주세요.

```
라이선스 1개 = 주 8블럭 = 32시간
```

### 분량에 따라 차등 배정하는 이유

렌더 시간은 **영상 길이에 거의 비례**합니다. 6분짜리와 2분짜리에게 같은 시간을 주면 6분짜리는 마감 안에 끝내지 못합니다.

| 프로젝트 분량 | 라이선스 | 주 타임블럭 | 주 사용시간 |
| --- | --- | --- | --- |
| 3분 이하 | 1 | 8 | 32시간 |
| 3분 초과 ~ 6분 이하 | 2 | 16 | 64시간 |
| 6분 초과 | 3 | 24 | 96시간 |

**라이선스 합계가 16을 넘으면** 주간 공급 128블럭을 초과합니다. 그때는 구간을 조정하세요.

### 상한이지 할당이 아닙니다

라이선스는 **"여기까지 예약할 수 있다"** 는 뜻이며, 블록은 선착순입니다. 학생 안내 시 이 점을 명확히 해주세요.

**심야 블록(23:00-03:00, 03:00-07:00)을 적극 권장해주세요.** 렌더는 사람이 지켜보지 않아도 돌아갑니다. 저녁에 제출하고 자면 되는데, 이걸 모르는 학생이 많아 저녁 시간대만 몰립니다.

## 4. 학생에게 배포할 것

| 자료 | 형태 | 내용 |
| --- | --- | --- |
| **렌더팜 가이드** | 노션 페이지 | 예약 → 파일 준비 → 제출 → 수령 전 과정 + 에러 해결 |
| **예약 시트** | 구글 시트 | 신청 및 예약 |
| **NAS 안내문** | 텍스트 | 실습실 PC에서 바로 읽는 요약본 |

가이드에는 **자주 발생하는 에러 10가지**와 해결법이 들어 있습니다. 학생 문의가 오면 먼저 그 페이지를 안내해주시면 대부분 해결됩니다.

### 작년과 달라진 점 — 학생에게 꼭 알려주세요

| 항목 | 작년 (PRFS 1.0) | 올해 |
| --- | --- | --- |
| **마야 컬러 매니지먼트** | 학생이 스크립트를 직접 실행 | **서버에서 처리 — 학생은 아무것도 안 해도 됨** |
| **업로드 경로** | `deadline_repo\renderfarm\학번\input` | `2026_renderfarm\학번\input` |
| **마야 버전** | — | **2026 고정** (Arnold 라이선스가 2026 전용) |
| **Render Device** | — | **CPU 고정** (GPU는 일부 프레임이 조용히 실패) |

경로가 바뀐 이유는 **학생 작업 영역을 Deadline Repository와 다른 볼륨으로 분리**했기 때문입니다. 작년에는 결과물이 쌓이면 Repository 볼륨이 차서 렌더팜 전체가 멈출 수 있는 구조였습니다.

### 리커버리 타임 — 올해는 두지 않습니다

작년에는 실패한 작업을 몰아서 다시 돌리는 **리커버리 타임**을 따로 운영했습니다. 올해는 **두지 않는 것으로 시작**합니다.

| | 내용 |
| --- | --- |
| **작년 (A안)** | 주 1~2블럭을 예약 불가로 비워두고 실패분 재처리용으로 사용 |
| **올해 (B안)** | 실패하면 학생이 본인 블럭에서 다시 돌림 |

B안으로 시작하는 이유는 두 가지입니다.

1. **작년에 실패를 만들던 원인이 대부분 해결됐습니다.** OCIO 환경변수, Arnold 라이선스 버전, GPU 메모리 부족 — 세 가지가 실패의 대부분이었고 지금은 모두 잡혀 있습니다.
2. **Pool 분할로 여유가 생겼습니다.** 네 팀이 동시에 돌 수 있어 재시도 비용이 작년보다 낮습니다.

운영 규칙은 적을수록 지켜지므로, 필요해지기 전까지는 두지 않는 쪽이 낫다고 판단했습니다.

> **시범 운영 중 실패가 잦으면 A안으로 전환하시면 됩니다.** 전환 방법은 간단합니다 — 예약표에서 주중 한두 블럭을 회색으로 막고 "리커버리" 라고 표시한 뒤, 그 시간에 실패한 작업을 재제출하면 됩니다.
>
> 전환 판단 기준: 한 주에 **실패 재시도가 전체 작업의 20%를 넘으면** 검토해볼 만합니다.

## 6. 운영상 꼭 지켜져야 하는 것

### ⚠️ 라이선스 서버 PC는 끄지 마세요

**M211-00** 이 Arnold 라이선스 서버입니다. 이 PC가 꺼지면 **실습실 전체의 마야 렌더가 전부 실패**합니다.

Deadline Monitor의 Worker 목록에서 M211-00이 Offline으로 보여도 정상입니다 — 라이선스 서버 역할과 렌더 Worker 역할은 별개입니다.

### 실습실 PC를 켜두세요

렌더팜은 **켜져 있는 PC만** 사용합니다. 예약 시간에 PC가 꺼져 있으면 그만큼 느려집니다. 수업 종료 후에도 PC는 켜둔 채로 두는 쪽이 좋습니다.

### 예약 시간 외 사용을 막아주세요

예약한 팀이 자기 그룹의 PC를 온전히 쓸 수 있어야 합니다. 예약하지 않은 시간에 Worker PC를 점유하면 다른 팀 렌더가 느려집니다.

### NAS 결과물을 비우게 해주세요

EXR 시퀀스는 한 프로젝트가 수십 GB까지 갑니다. 방치하면 NAS가 차서 **다른 팀이 렌더를 못 합니다.**

마감 주간에는 주 1회 정도 공지해주시면 좋겠습니다.
