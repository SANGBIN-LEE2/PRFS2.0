# ① 결과물이 회색으로 나온다

**이렇게 보입니다** — 모델은 있는데 텍스처가 안 입혀진 회색 덩어리.

**로그에 이게 있습니다**

```
WARNING | [texturesys] unable to load an image from the path: "D:/..."
```

**왜** — 텍스처 경로가 **내 PC**를 가리키고 있습니다. Worker PC에는 `D:\` 가 없습니다.

> ⚠️ **이 상태로도 렌더가 중단되지 않습니다.** 텍스처 없이 그대로 완료됩니다. 그래서 결과물을 봐야만 압니다.

**이렇게 하세요**

```
1  마야에서 씬 열기
2  Windows → General Editors → File Path Editor
3  빨간 줄 전부 선택
4  Repath Files → NAS의 텍스처 폴더 지정
5  빨간 줄이 0개가 될 때까지 반복
6  Ctrl+S 저장 후 다시 제출
```

# ② 캐릭터가 통째로 안 보인다

**이렇게 보입니다** — 배경은 나오는데 캐릭터나 특정 오브젝트가 통째로 없음.

**로그에 이게 있습니다**

```
Warning: Reference file not found. : D:/...
```

**왜** — 레퍼런스(Reference)가 안 읽혔습니다.

**이렇게 하세요**

```
1  마야에서 씬 열기
2  File → Reference Editor
3  레퍼런스 선택 → Reference → Import Objects from Reference
4  Ctrl+S 저장 후 다시 올리고 제출
```

> **남에게 파일을 받을 때는 `File → Archive Scene` 으로 받으세요.** 텍스처·레퍼런스·캐시가 전부 zip으로 묶입니다. 씬 파일만 받으면 수십 개가 한꺼번에 빠집니다.

# ③ Completed 인데 결과물이 없다

**왜** — 렌더가 초기에 중단됐는데 Deadline이 `Completed` 로 표시한 경우입니다. 실제로 자주 있습니다.

**이 순서로 확인하세요**

```
1  Task Time 이 몇 초인가?           → 그렇다면 렌더를 안 한 것
2  로그에 '100% done' 이 있는가?      → 없으면 렌더를 안 한 것
3  경로에 한글·공백·점이 없는가?       → 있으면 ⑤
4  출력 폴더가 실제로 존재하는가?      → 없으면 만들고 재제출
```

대부분 **⑤(경로 문제)** 로 이어집니다.

# ④ 장수가 모자란다

**이렇게 보입니다** — 10프레임 돌렸는데 결과물이 7장. Job은 `Completed`.

**로그에 이게 있습니다**

```
ERROR | [gpu] no GPU matching requirements found for GPU-rendering
Error: RuntimeError: [mtoa] Failed batch render
```

**왜** — `Render Device` 가 **GPU** 로 되어 있습니다. Arnold는 그래픽카드 메모리가 부족하면 CPU로 넘어가지 않고 **그냥 중단합니다.**

```
M211-05 : GPU 9420MB 여유  →  성공
M211-07 : GPU  373MB 여유  →  실패
```

같은 작업인데 **어느 PC에 걸리느냐에 따라** 갈립니다.

**이렇게 하세요**

```
1  Render Settings → Arnold Renderer → System
2  Render Device = CPU
3  Ctrl+S 저장 후 다시 제출
```

> 끝났다고 뜨면 **항상 장수를 세어보세요.** 10프레임 제출했으면 10장이어야 합니다.

# ⑤ 몇 초 만에 끝난다 / 씬을 못 찾는다

**왜** — 경로에 **한글·공백·점(`.`)** 이 있습니다. **가장 흔한 실수입니다.**

```
.../scenes/s03 c220/ Lighting/shot.mb     ❌  공백
.../scenes.mb/s03_c220/shot.mb            ❌  점
.../씬/조명/shot.mb                        ❌  한글
.../scenes/s03_c220/Lighting/shot.mb      ✅
```

**이렇게 하세요** — 폴더가 몇 개 안 되면 손으로 고치세요. 많으면 아래 스크립트를 쓰세요.

### 공백 한 번에 제거하기

```
마야 → Script Editor 열기
→ 하단 탭의 + 버튼 → Source Type 을 Python 으로
→ 아래 코드 붙여넣기 → Ctrl+A → Ctrl+Enter
```

```python
import os

def remove_spaces_recursively(root_folder):
    if not os.path.exists(root_folder):
        print("경로가 존재하지 않습니다: " + root_folder)
        return

    renamed_files = 0
    renamed_folders = 0

    # 하위 폴더부터 탐색해야 상위 이름이 바뀌어도 안전합니다
    for current_root, dirs, files in os.walk(root_folder, topdown=False):
        for file_name in files:
            if " " in file_name:
                old_path = os.path.join(current_root, file_name)
                new_path = os.path.join(current_root, file_name.replace(" ", ""))
                os.rename(old_path, new_path)
                print("파일 이름 변경: " + old_path)
                renamed_files += 1

        for dir_name in dirs:
            if " " in dir_name:
                old_path = os.path.join(current_root, dir_name)
                new_path = os.path.join(current_root, dir_name.replace(" ", ""))
                os.rename(old_path, new_path)
                print("폴더 이름 변경: " + old_path)
                renamed_folders += 1

    print("완료. 파일 %d개, 폴더 %d개 이름 변경." % (renamed_files, renamed_folders))


# ↓ 본인 프로젝트의 가장 상위 폴더 경로로 바꾸세요
folder = r"\\223.194.101.83\2026_renderfarm\input\C393169\20261103_final"
remove_spaces_recursively(folder)
```

> ⚠️ **이름이 바뀌면 씬 안의 텍스처 경로도 다시 잡아야 합니다.** 스크립트를 돌린 뒤 `File Path Editor` 로 빨간 줄을 확인하세요.
>
> 걱정되면 돌리기 전에 폴더를 복사해두세요.

3  다음부터는 Render Settings → Common → File name prefix 에

```

# ⑫ 이상한 폴더가 여러 개 생겼다

두 가지가 있습니다. **먼저 어느 쪽인지 구분**하세요.

## 이렇게 보입니다

```
20261103_final\
  ├ beauty\
  ├ background\
  ├ ID\
  ├ AA_inv_density\
  └ N\
```

### 👉 이건 정상입니다 — AOV 폴더

**AOV(렌더 패스)를 켜둔 씬이면 패스 이름으로 폴더가 하나씩 생깁니다.**

로그에서 확인할 수 있습니다.

```
[aov] done preparing 7 AOVs for 6 outputs to 4 drivers
```

**`beauty` 폴더가 최종 이미지입니다.** 나머지는 합성용 패스입니다.

패스가 필요 없으면 `Render Settings → AOVs` 탭에서 목록을 비우세요.

> `N`(노멀) 같은 패스는 **PNG로 저장되지 않아** 폴더가 비어 있습니다. 로그에 이렇게 뜹니다.
> ```
> [aov] driver "...driver_png.N" does not support VECTOR pixels
> ```
> 패스를 쓰실 거면 Image format 을 `exr` 로 두세요.

## 이건 잘못된 것입니다 — 경로가 두 번 붙음

```
20261103_final\
  └ beauty\
      └ 223.194.101.83\
          └ 2026_renderfarm\
              └ output\
                  └ C393169\
                      └ 20261017_old\
                          └ bd.0002.png
```

폴더 안으로 들어갈수록 **NAS 경로가 통째로 또 나오는** 경우입니다.

## 로그에 이게 있습니다

```
[driver_png] writing file
//223.194.101.83/.../20261103_final/beauty///223.194.101.83/.../20261017_old/bd.0002.png
                                           ↑ // 가 중간에 또 나옴
```

## 왜

제출 창의 `Output Path` 와 씬의 `File name prefix` **양쪽에 전체 경로가 들어가 있어서** Deadline이 두 경로를 그대로 이어 붙인 것입니다.

```
//...output/C393169/20261103_final  /beauty/  //223.194.101.83/...20261017_old/bd.0002.png
└──── 제출 창 Output Path ──────┘  └ AOV ┘  └──── 씬의 File name prefix ────────┘
```

**절대경로는 한 군데에만** 들어가야 합니다.

| 칸 | 어디에 | 넣을 것 |
| --- | --- | --- |
| `File name prefix` | Render Settings → Common | **파일 이름만** |
| `Output Path` | 제출 창 | **폴더 경로** |

## 이렇게 하세요

```
1  Render Settings → Common → File name prefix
   칸을 비우고 파일 이름만 넣기       예)  shot01

2  File name: 줄 확인
   shot01.0001.png                ← 경로가 없는 게 맞습니다
   <RenderPass>/shot01.0001.png   ← AOV 켜두셨으면 이렇게 보입니다

3  Ctrl + S 저장

4  제출 창의 Output Path 에 폴더 경로를 넣고 다시 제출
   //223.194.101.83/2026_renderfarm/output/내학번/날짜_작업명
```

> 이미 생긴 이상한 폴더는 지우셔도 됩니다. 안에 있는 이미지는 멀쩡하니, 필요하면 꺼내두고 지우세요.

# ⑬ Frame List 가 회색으로 잠겨 있다

## 이렇게 보입니다

제출 창의 `Frame List` 칸이 회색이고, 숫자 하나만 들어가 있어서 고칠 수가 없습니다.

```
Frame List       3        ← 회색. 클릭해도 입력이 안 됨
Frames Per Task  1
```

## 왜

**마야가 "애니메이션이 아니라 한 장만 렌더"로 설정돼 있기 때문**입니다. 그 상태에서는 프레임 범위를 정할 이유가 없으니 Deadline이 칸을 잠급니다.

## 이렇게 하세요

```
1  제출 창의  ▶ Additional Frame Options  를 펼쳐보세요
   안에 체크박스가 있으면 끄면 풀립니다

2  안 풀리면 마야로 가서
   Render Settings → Common 탭
```

| 칸 | 있어야 할 값 |
| --- | --- |
| **Frame/Animation ext** | `name.#.ext` |
| **Frame Range** Start / End | 렌더할 범위 (예: `1` / `3`) |

`Frame/Animation ext` 가 **`name.ext`** 로 되어 있으면 한 장짜리라는 뜻입니다. `name.#.ext` 로 바꾸세요.

```
3  Ctrl + S 저장
4  제출 창을 닫았다가 다시 열기
```

> 이 설정은 **블렌더의 `####`** 와 같은 역할입니다. 빠지면 여러 장을 돌려도 한 장만 남습니다.

# ⑭ Strict error checking 으로 중단됐다

## 로그에 이게 있습니다

로그 **맨 첫 줄**입니다.

```
Error: Strict error checking on, caught the following error or warning.
Warning: file: ... line 41: Error reading file. : //.../xxx_Rigging_master.ma
```

그리고 아래쪽에 이런 줄이 수백 개 반복됩니다.

```
Error: ... The transform 'FK_spine_1_ctl' has no '.oclr' attribute.
Error: ... setAttr: No object matches name: .oclr
```

## 왜

**렌더가 실패한 게 아니라 Deadline이 일부러 멈춘 것**입니다.

`.oclr` 은 **리그 컨트롤러 색깔** 속성입니다. 구버전 마야에서 만든 리그를 2026에서 열면 그 속성이 없어서 경고가 납니다. **렌더 결과에는 아무 영향이 없습니다.** 애니메이터가 보는 조종 막대기 색일 뿐입니다.

그런데 `Strict Error Checking` 이 켜져 있으면 Deadline이 **"Error"라는 글자만 보면 무조건 중단**합니다.

> **졸작 씬은 거의 다 이렇게 됩니다.** 선배들이 물려준 리그, 외주로 받은 리그가 구버전인 경우가 많습니다.

## 이렇게 하세요

제출 창에서 체크를 해제하고 **새로 제출**하세요.

```
☑ Use MayaBatch Plugin
☐ Strict Error Checking      ← 해제
```

Monitor 제출 창이면 `Advanced Options` 탭에 있습니다.

> **이미 제출한 Job은 Requeue 해도 똑같이 실패합니다.** 설정이 Job에 박혀 있어서, 해제한 상태로 다시 Submit 해야 합니다.

> 제출 창은 마지막에 쓴 설정을 기억합니다. 한 번 해제하면 그 PC에서는 계속 꺼진 채로 뜹니다.

## 중단되면 아무것도 확인할 수 없습니다

씬을 읽다가 멈춘 것이라 **Arnold는 시작도 안 했습니다.** 텍스처가 제대로 붙었는지, 카메라가 맞는지 전부 확인이 안 됩니다. 이것부터 풀어야 다음이 보입니다.

# ⑮ 렌더는 됐는데 내용이 엉뚱하다

장수는 맞는데 **화면이 비어 있거나, 캐릭터가 가만히 있거나, 집에서 뽑은 것과 다른** 경우입니다.

## 왜

**씬의 실제 프레임 범위를 벗어난 구간을 렌더한 것**입니다.

```
씬의 실제 범위    1001 ~ 1041
Frame List        1-3        ← 애니메이션 시작 전 구간
```

졸작 씬은 **대부분 1001번부터 시작합니다.** 프로덕션 관행입니다. `1` 부터 시작하는 씬이 오히려 드뭅니다.

## 이렇게 하세요

```
1  마야에서 씬을 열고 아래쪽 타임라인의 시작·끝 숫자를 봅니다
   또는  Render Settings → Common → Frame Range

2  그 범위로 Frame List 를 다시 적습니다
   1001-1003        처음 3장 테스트
   1001-1041x5      5프레임 간격으로 전체
```

> 집에서 받은 결과물 파일 이름을 보면 바로 알 수 있습니다. `shot_1001.exr` 이면 1001부터 시작하는 씬입니다.
