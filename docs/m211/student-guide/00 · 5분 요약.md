# 📋 00 · 5분 요약

전체 흐름만 먼저 보고 싶을 때 읽으세요. 각 단계의 자세한 내용은 해당 페이지에 있습니다.

---

## 전체 흐름

```
1  예약            예약 시트에 내 학번 입력
2  이름 정리        폴더·파일 이름에서 한글·공백·점 제거  ← 올리기 전에
3  NAS 업로드       프로젝트 폴더를 통째로 올림
4  파일 준비        NAS에 올린 씬을 열어서 정리하고 거기에 저장
5  제출            예약한 시간에 실습실 PC에서 Deadline에 제출 (먼저 3프레임)
6  확인            Deadline Monitor에서 진행 상황 확인
7  수령            NAS output 폴더에서 받고, 폴더 비우기
```

> **올리는 게 먼저, 고치는 건 그 다음입니다.** 텍스처 경로를 NAS로 바꾸려면 텍스처가 이미 NAS에 있어야 합니다. 그리고 **NAS에 올린 씬을 열어서 고치고 거기에 저장**하세요. 집에 있는 파일을 고치면 NAS 쪽은 그대로입니다.

---

## 경로 세 줄

이것만 외우면 절반은 끝납니다.

| 용도 | 경로 |
| --- | --- |
| **올리는 곳** | `\\223.194.101.83\2026_renderfarm\내학번\input\날짜_작업명\` |
| **받는 곳** | `\\223.194.101.83\2026_renderfarm\내학번\output\날짜_작업명\` |
| **안내문** | `\\223.194.101.83\2026_renderfarm\00_READ_ME_FIRST\` |

## 마야 설정 4개

| 어디서 | 무엇을 |
| --- | --- |
| `File → Reference Editor` | 레퍼런스를 **Import** 로 변환 |
| `Windows → General Editors → File Path Editor` | **빨간 줄 0개** 로 만들기 |
| `Render Settings → Arnold → System` | Render Device = **CPU** |
| `Render Settings → Common` | File name prefix = **파일 이름만** (`shot01`) |

마지막에 `Ctrl + S`. 저장 안 하면 아무 의미 없습니다.

> 마야 **버전은 신경 안 쓰셔도 됩니다.** 렌더팜이 어떤 버전 씬이든 2026으로 렌더합니다.

---

## 블렌더 설정 3개

| 어디서 | 무엇을 |
| --- | --- |
| `File → External Data` | **Pack Resources** |
| `Output Properties → Output` | NAS 출력 경로 + 끝에 **`####`** |
| `Render Properties` | Device = **CPU** |

마지막에 `Ctrl + S`.

## 예약 구조 한눈에

```
타임블럭 = 4시간
평일 19:00~11:00 (4블럭)   ·   주말 24시간 (6블럭)
PC는 4개 그룹  →  한 시간대에 4팀이 동시에 렌더
```

예약할 때 **시간 + 레인**을 고르고, 제출 창의 **`Pool`** 에 같은 레인을 지정합니다. (`Group` 은 `none` 그대로)

## 자주 나는 실수 Top 10

| | 실수 | 결과 |
| --- | --- | --- |
| 1 | 씬 파일만 올림 (프로젝트 폴더 통째로 X) | 텍스처가 회색으로 나옴 |
| 2 | 폴더 이름에 한글·공백 | 씬을 못 찾고 바로 끝남 |
| 3 | 블렌더 출력 경로에 `####` 빠짐 | 100프레임 돌려도 **1장**만 남음 |
| 4 | Render Device 가 GPU | 일부 프레임만 조용히 실패 |
| 5 | 카메라를 안 고름 | persp 뷰로 렌더됨 |
| 6 | Pool을 잘못 고름 | 예약 안 한 PC를 써서 남의 작업과 겹침 |
| 7 | 저장 안 함 | 설정이 하나도 반영 안 됨 |
| 8 | prefix 와 Output Path 양쪽에 전체 경로 | 경로가 이어 붙어 폴더 안에 폴더가 생김 |
| 9 | 씬의 프레임 범위를 확인 안 함 | 엉뚱한 구간이 렌더됨 (씬마다 범위가 다릅니다) |
| 10 | Strict Error Checking 때문에 막힘 | 무해한 경고 하나로 작업이 중단 |
